# QA Framework Consolidation

The root Playwright framework is the repository's single source of truth. This inventory records the review of the retired nested framework before its removal.

| Nested item                                              | Root equivalent                                                                     | Unique value                                                                                                                                                | Action                                            |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `package.json`, `package-lock.json`, and `tsconfig.json` | Root `package.json`, `package-lock.json`, and `tsconfig.playwright.json`            | None; separate dependency tree duplicated root tooling.                                                                                                     | Remove.                                           |
| `playwright.config.ts` and nested workflow               | Root Playwright configurations and root workflows                                   | None; root adds cross-browser coverage, type checking, artifacts, and safety-gated live smoke.                                                              | Remove.                                           |
| `fixtures/`, `pages/`, and `utils/`                      | `tests/test-data/`, `tests/pages/`, `tests/fixtures/`, and mocked support utilities | None; root equivalents are typed and used by active tests.                                                                                                  | Remove.                                           |
| `tests/e2e/`                                             | `tests/e2e-mocked/` and `tests/smoke-live/`                                         | No unique supported scenario; nested tests duplicate role, lifecycle, and permission coverage while directly writing to a configured target.                | Remove.                                           |
| `tests/api/`                                             | Jest/Supertest API tests and configured live-smoke coverage                         | No unique supported scenario; authentication, authorization, validation, CRUD, and health behavior are already covered without a second live API framework. | Remove.                                           |
| `docs/TRACEABILITY_MATRIX.md`                            | `docs/TEST_PLAN.md`                                                                 | Compact requirements-to-root-coverage mapping.                                                                                                              | Migrated as the **Traceability Summary** section. |
| `docs/TEST_STRATEGY.md` and `docs/TEST_CASES.md`         | `docs/TEST_PLAN.md`, `docs/TEST_CASES.md`, and `docs/QA_ARCHITECTURE.md`            | None; root documents are more complete and reflect the active three-browser framework.                                                                      | Remove.                                           |
| `docs/BUG_REPORTS.md`                                    | `docs/BUG_REPORT_EXAMPLES.md`                                                       | None; nested reports are hypothetical regressions contradicted by current passing root tests.                                                               | Remove.                                           |
| `README.md`                                              | Root `README.md` and QA documentation                                               | None; described a competing standalone framework.                                                                                                           | Remove.                                           |

If the retired framework is ever needed as a standalone portfolio repository, recover it from Git history and re-establish its own documentation, dependencies, and CI outside this application repository.
